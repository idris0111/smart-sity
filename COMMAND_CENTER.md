# Smart City Command Center

Работа идёт в существующем проекте. PostgreSQL, модели бронирования, JWT,
permissions, Redis/Celery/Channels и Django Admin сохранены. Новые части интерфейса
написаны на TypeScript. Авторизация и существующие формы продолжают работать.

## Дорожный маршрут

`GET /api/route-paths/{number}/` читает остановки `RouteStop` в порядке `order`,
запрашивает driving route у OSRM и сохраняет полный GeoJSON LineString в
`RouteGeometry`. `[longitude, latitude]` — порядок координат GeoJSON.
Поле `coordinates` с `[latitude, longitude]` сохранено для совместимости.

Геометрия инвалидируется изменением координат или порядка остановок через хеш.
Отказ провайдера возвращает 503. Прямой линии между остановками нет.
Остановки допускаются в пределах 150 метров от дороги. Текущий маршрут 88:
590 точек, около 19 км, 8 остановок, привязка к дороге 1–27 метров.
Это демонстрационная последовательность остановок, а не официальный автобусный маршрут.
Дорожный граф учитывает автомобильные дороги и направления движения OSM;
он не содержит ведомственных схем автобусных линий и актуальных перекрытий.

По умолчанию используется публичный development OSRM. Для постоянного сервиса
задайте `ROUTING_URL` своего OSRM. [Документация OSRM](https://project-osrm.org/docs/v5.24.0/api/).

## Карта и интерфейс

Главная страница и карта используют MapLibre/react-map-gl, OpenFreeMap,
GeoJSON-маркеры, кластеры камер и heatmap событий. Слои сохраняются в localStorage.
Есть выбор объекта, слежение за транспортом, поиск по базе, полноэкранный просмотр
камер, мобильная панель и индикаторы реального подключения.
Ctrl+K открывает command palette; поиск поддерживает тип и ID объекта, например
`camera 12`, `route 7` или `bus 14`. AI доступен в боковой панели карты и на отдельной странице.
3D-здания берутся из OSM, поэтому высоты и наличие зданий зависят от покрытия.
Карта и HLS.js загружаются отдельно по мере необходимости.

При желании настройте `VITE_MAP_STYLE` и `VITE_TERRAIN_URL` в
`frontend/.env.local`. Рельеф по умолчанию использует публичные глобальные
Mapzen Terrarium tiles; проверена доступность тайла района Душанбе.
Terrain URL можно заменить шаблоном `{z}/{x}/{y}` или raster-dem TileJSON.
Для шаблона Mapbox RGB укажите `VITE_TERRAIN_ENCODING=mapbox`.
[Форматы Mapzen DEM](https://github.com/tilezen/joerd/blob/master/docs/formats.md).
[OpenFreeMap](https://openfreemap.org/quick_start/), [MapLibre terrain](https://maplibre.org/maplibre-gl-js/docs/examples/3d-terrain/).

Демо-объекты существующей базы отмечены DEMO. Переключатель DEMO MODE скрывает
демо-маркеры и демонстрационную дорожную линию. Seed не запускается автоматически.
Реальные камеры или события не подменяются выдуманными источниками.

## Камеры

1. Добавьте точные разрешённые имена сервера камеры и CDN в `CAMERA_ALLOWED_HOSTS`.
2. Для собственных камер локальной сети задайте `CAMERA_ALLOW_PRIVATE=1`.
3. Создайте камеру через раздел камер или Django Admin. Подтвердите право использования.
4. Выберите HLS, MJPEG, SNAPSHOT, WEBRTC или EXTERNAL.

Для HLS/MJPEG нужен HTTP(S)-адрес соответствующего потока. Для превью и AI
укажите `preview_url` с JPEG/PNG; HLS-плейлист не является снимком.
Для WEBRTC нужен WHEP endpoint шлюза, принимающий SDP offer клиента.
WebRTC ICE/media идут к вашему шлюзу, SDP и удаление сессии — через JWT API.
EXTERNAL предназначен для публичного embed URL без query/fragment с секретами;
страница должна разрешать встраивание. Iframe изолирован sandbox.
RTSP и произвольные проприетарные WebRTC-сигнальные протоколы требуют шлюза.
Базовый offer/answer соответствует [WHEP](https://www.ietf.org/archive/id/draft-ietf-wish-whep-04.html).

Адреса HLS/MJPEG и снимков не входят в обычный JSON камер. Для медиапрокси
выдаётся зашифрованный билет на 5 минут, связанный с камерой и пользователем.
Редиректы и HLS assets повторно проверяются по allowlist. Отключение камеры
отзывает доступ. MJPEG/сегменты передаются асинхронно для Daphne/ASGI;
Nginx не буферизует поток.

Endpoints: `/api/cameras/`, `/{id}/`, `/map/`, `/nearby/?lat=&lng=&radius_m=`,
`/{id}/status/`, `/{id}/access/`, `/{id}/stream/`, `/{id}/snapshot/`, `/{id}/whep/`.
Чтение требует JWT, изменение — staff. Без конфигурации источников камер список пуст.

## Redis, Celery и WebSocket

Compose явно задаёт `USE_REDIS=1`. Redis хранит cache, broker и Channels в разных DB.
Beat проверяет камеры каждые 60 секунд, завершает брони, при `DEMO_SIMULATION=1`
передвигает только `DEMO-88-01` по сохранённой дороге каждые 10 секунд.
До расчёта дорожной геометрии симулятор не перемещает транспорт.

WebSocket `/ws/city/` принимает JWT в первом сообщении, проверяет origin и срок
токена. Camera/vehicle/parking updates общие; обращения, брони, AI-alerts остаются
ограничены владельцем/оператором. `/api/system/status/` сообщает реальную доступность
PostgreSQL, Redis и Celery worker. При `USE_REDIS=0` REST работает, WS отключён.
При отключённом WS транспорт, камеры и свободные места обновляются REST-запросами
раз в 15 секунд на видимой вкладке. Счётчики парковки распространяются через WS
без владельцев и деталей чужих броней.

На этом компьютере Redis/worker/Beat не запущены; Docker Linux engine требует
доступного WSL. Код очереди и Channels проверен тестами, запуск через настоящий
Redis в этой сессии не подтверждён. Интеграционный сценарий остаётся в
`scripts/integration_realtime.py`.

## AI и внешние слои

Синий акцент по умолчанию теперь общий для входа, регистрации, панели и карты.
В верхней панели можно выбрать красный или зелёный; выбор сохраняется в браузере
(`smart-city-accent`) и синхронизируется между вкладками. Тёмная/светлая тема независима от цвета.

Для свободного общения AI нужен `SMART_CITY_AI_URL` + `SMART_CITY_AI_KEY` (только backend).
Без сервиса работает явно подписанный локальный справочник: приветствия, помощь,
парковки с актуальным числом свободных мест, маршруты и разрешённые камеры.
Он не является языковой моделью. При отказе gateway включается справочник
с сообщением о недоступности AI. Анализ снимков по-прежнему требует AI и очереди.
Ассистент принимает `message`, `language` (ru/en/tg) и `history`
(до 12 сообщений `{role: user|assistant, content}`, каждое до 4000 символов).
История хранится только в открытом чате; «Новый разговор» её очищает.
Ответ включает `mode: ai|guide` и `degraded` для честного обозначения режима.
Ассистент передаёт ограниченный контекст текущего пользователя без stream URLs,
ключей, имён пользователей и e-mail. Gateway возвращает `{answer, actions}`;
действия карты проверяются по разрешённым типам и доступным ID.

`POST /api/cameras/{id}/analyze/` создаёт Celery-задачу анализа одного снимка.
Результат получает статус REVIEW, а не подтверждённое происшествие.
Оператор подтверждает/отклоняет через `/api/ai-alerts/{id}/review/`.
Подтверждение атомарно создаёт одно событие; повторное подтверждение запрещено.
Без ключа или очереди возвращается 503.

Weather/air/traffic/POI/crowd/news — подключаемые серверные GeoJSON-источники:
`CITY_LAYER_{WEATHER|AIR|TRAFFIC|POI|CROWD|NEWS}_URL` и необязательный `_TOKEN`.
Их `/api/layers/{key}/` кеширует на 60 секунд. В интерфейсе неподключённые слои
отключены; данные о погоде, пробках или плотности людей не генерируются.

## PostGIS

Lat/lng и действующий PostgreSQL backend сохранены. Когда в сервере появится
PostGIS, выполните `python manage.py prepare_postgis`: команда атомарно добавит
generated WGS84 point columns и GiST индексы, не меняя REST-поля.
Повторное выполнение допустимо. В текущей PostgreSQL PostGIS отсутствует,
поэтому пространственные индексы пока не создавались. Nearby работает через
bounding box и haversine. Радиус ограничен 25 км.

## Проверка

```powershell
& .\.venv\Scripts\python.exe manage.py check
& .\.venv\Scripts\python.exe manage.py test --settings=core.test_settings
cd frontend
npm.cmd run typecheck
npm.cmd run build
npm.cmd run test:i18n
npm.cmd run smoke
```

Smoke использует настоящий Vite proxy и PostgreSQL, создаёт временного пользователя
и удаляет его после теста. Проверяет JWT, подробную дорогу, cameras/GeoJSON/system,
бронирование, пересечения, отмену, события и обращения.
Рендер-проверка охватывает новые страницы на ru/en/tg.
Проверка в живом браузере была остановлена инструментом Computer Use: он не смог
достоверно определить URL браузера. Скриншоты и визуальная проверка не подтверждены.
