# Smart City API

Учебный backend на Django REST Framework. Существующие модели находятся в `myapp/models.py`, пользователь — в `accounts/models.py`. Новую модель пользователя создавать не нужно.

## Запуск

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py loaddata dushanbe_locations
.\.venv\Scripts\python.exe manage.py runserver
```

Проверка:

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test
```

Это настройки для локальной разработки. Перед публикацией нужно вынести `SECRET_KEY` из кода, отключить `DEBUG` и настроить `ALLOWED_HOSTS`.

## Авторизация и адреса

Регистрация: `POST /account/register/` с `username` и `password`. Вход: `POST /account/login/` с теми же полями. Ответ содержит `access` и `refresh`. Для защищённых запросов нужен заголовок `Authorization: Bearer <access>`. Обновление токена: `POST /account/token/refresh/` с `refresh`. Профиль: `GET`, `PUT`, `PATCH /account/profile/`. Выход с отзывом refresh токена: `POST /account/logout/`. Старый префикс `/auth/` продолжает работать.

Ресурсы под `/api/`: `parkings/`, `parking-spots/`, `bookings/`, `stops/`, `routes/`, `route-stops/`, `vehicles/`, `incidents/`, `service-requests/`. Для каждого списка работают `GET` и `POST`, для объекта `/<id>/` — `GET`, `PUT`, `PATCH`, `DELETE`. Документация: `/swagger/` и `/redoc/`.

Поиск прямого маршрута: `GET /api/routes/search/?start_stop=ID&end_stop=ID`. Он возвращает активные маршруты, где начальная остановка стоит раньше конечной. Пересадки не ищет. Остановки маршрута добавляются через `POST /api/route-stops/` с `route`, `stop` и `order`; в ответе `stop_details` содержит координаты.

## Как устроены основные файлы

- `models.py` задаёт таблицы и связи. `RouteStop` хранит порядок остановок. Уникальные ограничения защищают порядок и остановку в пределах маршрута, включая записи через Django Admin.
- `serializer.py` превращает модели в JSON и проверяет входящие поля. При бронировании проверяются время, доступность места и пересечение с активными бронями. Поля владельца только для чтения.
- `permissions.py` отделяет чтение городских данных от записи администратором и защищает личные объекты.
- `views.py` использует Generic Views. `get_queryset()` оставляет обычному пользователю только свои брони, происшествия и обращения. `perform_create()` подставляет `request.user`.
- `urls.py` связывает адреса с views. JWTAuthentication в `core/settings.py` определяет `request.user`; permission решает, какое действие ему разрешено.

Городские объекты могут читать авторизованные пользователи, изменять — сотрудники (`is_staff`). Пользователь создаёт и изменяет свои брони, происшествия и обращения. Администратор видит и меняет все. Статус обращения `DONE` или `IN_PROGRESS` назначает администратор. Парковочные места и транспорт добавляются администратором только после проверки реальных данных.

## Исходные геоданные

Фикстура `myapp/fixtures/dushanbe_locations.json` содержит координаты, опубликованные для объектов OpenStreetMap. Координаты парковок обозначают точку объекта, а не номер отдельного парковочного места. Адреса оставлены пустыми, поскольку источники не дают подтверждённого адреса. Парковки `is_active=false`: их доступность для бронирования и инвентарь мест ещё не подтверждены.

Данные карты OpenStreetMap распространяются по ODbL; при отображении карты и объектов указывайте © OpenStreetMap contributors. [Министерство транспорта Таджикистана](https://mintrans.tj/en/surface-transport-city-routes-details/1) публикует номера и описания автобусных маршрутов, но эта страница не даёт полного проверенного порядка остановок и координат линии. Поэтому фикстура не создаёт маршруты или RouteStop с предположениями. Их надо сверить с источником перед загрузкой. Live GPS транспорта и камера пока не подключены.

Проверка пересечения бронирований рассчитана на учебный запуск. При реальных одновременных бронированиях одного места нужна дополнительная защита на уровне транзакций и подходящей базы данных; SQLite не поддерживает ограничение по пересечению временных интервалов.

## Короткие ответы для преподавателя

- **Model** — описание таблицы базы данных. `ForeignKey` связывает строки: бронь с пользователем и местом, остановку маршрута с маршрутом и остановкой.
- **Serializer** — проверяет входной JSON и формирует выходной JSON. В `ParkingBookingSerializer.validate()` отклоняется пересечение времени.
- **Permission** — разрешает или запрещает запрос. JWTAuthentication сначала определяет пользователя по токену.
- **Generic View** — готовый класс DRF для стандартного CRUD; поэтому в views остаётся только логика доступа и владельца.
- **`get_queryset()`** — выбирает записи, которые пользователь вообще может увидеть.
- **`perform_create()`** — задаёт владельца при сохранении; клиент не может выдать себя за другого пользователя.
- **`RouteStop`** — связь маршрута и остановки с номером её порядка. `CASCADE` удаляет зависимые записи вместе с родителем; `SET_NULL` оставляет Vehicle без удалённого маршрута.
